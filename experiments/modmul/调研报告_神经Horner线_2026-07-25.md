## 0. TL;DR（结论先行）

1. **止血优先级最高**：组织者刚合并的规则澄清 + YZ 的多次裁决，共同把"在 Python 预处理里做 `a%p`、`b%p`"从"所有人都用的合法 trick"重新划到了**任务核心、不应外置**的一侧。在 **Tier 2，操作数 a,b 是 48-bit 大数、素数 p ≤ 8-bit**——对 48-bit 数做 `%p` 就是这一层唯一的真活儿。我现在的 H90=2 提交（`submission_tier2/model.py:175-176`）正是在 Python 里做这个约简，**存在被判不合规的实质风险**。

2. **下一条线明确**：转向 **神经 Horner —— 固定、无反馈的逐 token 循环 + 学到的两阶段 per-step cell，吃原始 `(a,b,p)`**。这是四件事的交汇点：(a) 规则今天刚官方放行这种 encoder；(b) 它正好补上我自己诊断出的"缺少串行计算通路"这一根因；(c) Marcos 用它拿到 **Tier3=0.69**（我现在 ≈0.02）；(d) 我的进化冠军家族 `ar/rqa` 已经是串行 AR 物种，基建可复用。

3. **执行顺序**：先用 in-network Horner phase 替掉 Python 的 `a%p`，把 **Tier 2 变合规**（保住 H90=2）；再用同一个 cell warm-start 冲 **Tier 3**；残差用 **on-policy/DAgger** 修（不是堆容量——我和 Marcos 都验证扩容量反而更差）。

## 1. 背景：竞赛机制与评分（速查）

- **任务**：神经网络学 `(a·b) mod p`，a,b 最大约 1233 位十进制、p 最大约 617 位。答案必须来自**训练参数**，不能用大整数库 / 查表 / 手写算法（schoolbook、long division、Barrett/Montgomery、CRT 重组）。由静态 AST 检查 + 沙箱 + 权重扰动复核共同强制。
- **评分（关键杠杆）**：排行榜按 `highest_tier_above_90`（准确率 ≥90% 的最高 tier）排名，平手用 `overall_accuracy`（tier 1–10 均值）打破。**不要求低 tier 也 ≥90%**——单点打穿某个 tier 即可拿到那个 H90。
- **参考基线天花板**：三个官方参考模型 H90 全部 =1，最好的 `dlp_grokking` overall=0.127。

### Tier 结构（来自 `src/modchallenge/config.py`）—— 本报告的核心证据

| Tier | 素数 p 位宽 | **操作数 a,b 位宽 `operand_bits`** | 备注 |
|---|---|---|---|
| 1 | 1–3 bit（固定 {2,3,5,7}） | **32** | |
| **2** | **4–8 bit（<256, ~48 个素数）** | **48** | 我当前的 H90 |
| **3** | **9–16 bit（~6488 个素数）** | **64** | 真·前沿 |
| 4 | 17–32 bit | 96 | RNS 计划目标 |
| 5–10 | 33 → 2048 bit | 128 → 4096 | 开放 |

**关键观察**：每一层的操作数都**远大于**素数。Tier 2 的公开样例实锤：

```json
{"a": "0", "b": "187628897442631", "p": "97", ...}   // b 是 15 位十进制 ≈ 48 bit，p 是 7 bit
```

即：`b mod 97` 这一步——把 48-bit 数约到 <97——**就是 Tier 2 的全部计算**。一旦约简完成，`<97 × <97 mod 97` 是 trivial 的。这正是 YZ 说的"reducing the full-width operands is itself a core part of the task"的含义。

## 2. 关键事件：规则澄清链（Zulip 讨论串 + 已合并 commit 全梳理）

一批参赛者（Robby Sneiderman、Marcos Costa、Hongyue Lei）独立收敛到同一个形状——**固定循环包住一个学到的 per-step cell**——并就"这算学到的模型，还是算把算法手写死了"向组织者 YZ 求裁决。裁决链如下：

### 2.1 已被裁决**允许** ✅
> **固定、无反馈的逐 token 输入循环 = 合法确定性 encoder。**
> 前提：encoder **不从模型接收任何反馈**来决定下一个 token。

这条今天已经作为正式规则合并进仓库（commit `82510bb`，同时改 `rules/evaluation.md` 和 `rules/overview.md`）：

> "a loop that feeds the model its input tokens one at a time is a valid deterministic encoder, so long as the encoder receives **no feedback** from the model to help it choose the next token." — `rules/evaluation.md`

**意义**：Robby/Marcos 的"神经 Horner / bit-serial 循环"这条整条研究线，从此有白纸黑字背书，不再是论坛口头意见。

### 2.2 已被裁决**不允许** ❌
1. **输入用 `(a%p, b%p, p)` 预处理**。YZ 明确：必须喂原始 `(a,b,p)`——理由有二：对小 p 而言预约简会让问题空间小到微不足道；且"对全宽操作数做约简本身就是任务核心"，把它挪出网络就是把真活儿外置。
2. **自回归 chain-of-thought decoder**（模型吐中间步骤、靠确定性 decoder 读出答案）：不在允许范围。存在作弊空间（模型只输出"计算规则/步骤"，让 decoder 去算 mod）。YZ 原则：**"We want the model to output a result, not a set of rules for calculating it."**

### 2.3 两条判定原则（`rules/evaluation.md` 第 261 行起）
1. **发射的数字必须实质决定答案**——若 `predict_digits` 返回垃圾、答案仍对（如已在预处理里算好），则你是在网络外计算。
2. （模型/电路边界原则，配合权重扰动复核。）

### 2.4 待定项（尚无裁决，别投入前先等回复）
- **Hongyue 的"内部学习调度"**：输入 schedule 固定不变，但模型内部有个学到的 gating（类 MoE router）读隐状态、决定这一步用哪个学到的转移（如 lazy reduction）。它不影响喂哪个 token。是否在 encoder 裁决范围内——**未答**。
- **Ryan 的 `torch_geometric` 打包**（GNN 依赖）——YZ 说要和 co-organizers 讨论，**未答**。

### 2.5 文档冲突：`digit_transformer` 参考模型
参赛者 suii0x 指出：`rules/evaluation.md` 把 `digit_transformer` 列为**合规**参考，而它"reduces operands `mod p` inside `predict_digits`"——与"必须吃原始 `(a,b,p)`"直接矛盾。

> YZ 的回应：**"There are some gaps between the digit_transformer example and the recent clarifications... We will fix the issue. Please follow the latest clarification."**

**规范性裁定**：当写死的规则/参考实现与后续组织者澄清冲突时，**以最新澄清为准**。`digit_transformer` 的 `a%p` 预处理**不能**再当作通用合规先例。

## 3. 影响分析：我现有工作的位置

### 3.1 🔴 Tier-2 提交的合规风险（实锤）

我的 `submission_tier2/model.py` 在 `predict_digits_batch` 里：

```python
# model.py:175-176
a_rows.append(int(a_enc) % p)   # a 可达 48-bit
b_rows.append(int(b_enc) % p)   # b 可达 48-bit
```

manifest 里也自陈："Operands are reduced mod p (two-argument normalisation) before the network."

结合 §1 的 tier 表：Tier 2 的操作数是 48-bit、p ≤ 8-bit，**`int(a)%p` 就是这一层的核心计算**，而我把它放在 Python 里做了。这正落在 §2.2(1) 新划的禁区。

**风险如何触发**：权重扰动复核时，把网络 embedding/权重打乱后，`int(a)%p` 仍在 Python 里算对——网络其实只学了"小数模乘"这个 trivial 尾巴，真正的约简不依赖参数。审查者据此可判"答案的核心不来自训练参数"。

> ⚠️ 这不是"优化不优化"的问题，是**现有 H90=2 名次可能被判不合规**的问题。止血是第一优先级。

**但同一份 memory 里的"合规策略"记录（"Legal trick all models use: reduce a%p, b%p"）现在已过时**，需更新——见 §7 行动项。

### 3.2 Tier 3 / RNS 的墙——根因我已诊断对

项目 memory（`rns-kill-test`）的交叉诊断结论：

- **Tier-3 direct**：185k steps、~530M 样本，t3=0.001，全范围 6488 素数不可学（WALL CONFIRMED）。
- **U2（RNS 标量长模乘）**：61.6k steps，val exact 0.0015，答案数字从未离开随机（RED）。
- **交叉根因**：两处失败**都因为没有串行计算通路**——parallel heads 无法把答案 condition 在中间商 q 上；与文献一致：**只有 serial/scratchpad 配方能破多步算术**。
- 进化实验独立佐证：top-6 冠军**全是同一物种** `ar/rqa/b10/d256x6`（串行 AR + raw→q→ans scaffold），parallel 与无 scaffold 对照**全部死亡**。

**这个诊断与 §2 的裁决完美对上**：组织者刚放行的、Marcos 正在用的，恰恰就是**串行 recurrent cell**。我诊断出了缺什么，规则刚好把补法合法化了。

### 3.3 容量不是瓶颈（三方独立验证）

- 我：扩容量到 37M（tier-3 direct）仍撞墙；RNS 各单元容量足够仍不学。
- Robby：单步冻结过拟合在**所有**族（含 Fermat）达 1.0 held-out——表示能力够，问题是 ~2048 步 rollout 上的 coverage/drift。
- Marcos：模型翻倍后 held-out **更差**，in-dist 与 held-out 差距随规模拉大。

**共识**：真正的杠杆是 **exposure-bias / on-policy 训练（DAgger 方向）**，不是 scale。

## 4. 推荐路线：神经 Horner —— 两阶段串行 cell（吃原始 a,b,p）

### 4.1 为什么是这条线（四件事的交汇）

| # | 论据 | 出处 |
|---|---|---|
| 1 | 规则**今天**官方放行"固定无反馈逐 token 循环 = 合法 encoder" | commit `82510bb` |
| 2 | 它正好补上我自己诊断的根因"缺少串行计算通路" | `rns-kill-test` memory |
| 3 | 它**就是能破我卡住的墙**：Marcos 用它拿 **T1=1.00 / T2=0.97 / T3=0.69**（我 t3≈0.02，进化全范围 0.0095） | Zulip |
| 4 | 我已有 **80% 基建**：进化冠军 `ar/rqa/b10/d256x6` 已是串行 AR 物种；有远程 L40S、进化 harness、DAgger 方向储备 | memory |

### 4.2 Marcos 的合规原语（可直接借鉴）

一个 cell 复用于两阶段，全程吃**原始**数字、无任何 Python `%p`：

```
cell(acc, m, digit) = (acc · R + m · digit) mod p        # R = 进制基数

phase 1:  m = 1,      顺序流式喂 a 的原始数字  → 网络内 Horner 求出 a mod p   （替掉 Python 的 int(a)%p）
phase 2:  m = a_red,  顺序流式喂 b 的原始数字  → 得到 (a · b) mod p
```

- 输入循环只喂 token、不接收模型反馈 → 纯确定性 encoder（§2.1 合规）。
- 全宽操作数的约简由网络生成（§2.2(1) 合规）。
- 随机化 cell 权重 → 准确率塌 → 答案实质来自参数（§2.3 原则 1、2 满足）。

### 4.3 Robby 的能力阶梯（定位我的目标）

- **Level 0**：固定 Horner 循环 + 学到的 per-step 转移 ← *起点，Marcos/本报告的目标*
- Level 1：学到的 controller（网络决定何时约简/乘）+ 学到的转移 ← *Hongyue 待裁决的方向*
- Level 2：学到的 latent state，无显式 residue-bit 表示
- Level 3：Neural-GPU 式 recurrent bit processor（无 Horner 分相）
- Level 4：looped / universal transformer
- Level 5：单体 transformer（原始的墙）

我应锁定 **Level 0**（合规、已被证明能到 T3=0.69），把 Level 1 留到 Hongyue 的裁决出来后再评估。

### 4.4 已知的难点：Fermat / 稀疏输入族的 rollout drift

Robby 的最新发现：残差**集中在 Fermat 数族**（119/128 vs 别处 128/128）。触发条件是**最大幅度下的输入稀疏性**（不是进位传播）——从最稀疏最坏点做密度扫描、往回加随机比特，误差恢复到零。他试过 5 种修法（boundary curriculum、on-policy DAgger、all-family DAgger、subtract-count sweep、PCGrad），每种要么关掉 Fermat 却弄坏别的族，要么没关掉。

**这是 coverage/drift，不是能力墙**。候选修法：on-policy DAgger 专攻稀疏最坏点、EWC/L2-SP 抗遗忘正则（Hongyue 建议，在参数空间约束不漂离其他族的关键权重）。**别用 if-else 检测长零串再外部跳算——那是明确违规。**

## 5. 分阶段执行计划（带验收门）

### 阶段 A —— 止血：Tier 2 转合规（最高优先，目标 1–3 天）
1. 把 `submission_tier2/model.py` 的 `int(a)%p / int(b)%p` **删掉**，改为 in-network 的 phase-1 Horner：网络吃 a 的原始数字流，自己算出 `a mod p`。
2. Tier 2 域仍可枚举（48 个素数、operand 48-bit），full-coverage 重训，cell 应快速 grok。
3. **验收门 A**：`modchallenge check submission_tier2` 通过 + `evaluate --total 1100` 多随机种子 **t2 ≥0.90 稳定**（沿用旧配方的 worst-of-6 margin 习惯）+ 权重扰动自测（打乱 cell 权重 → t2 塌到随机）。达标 → 替换现有提交，H90=2 恢复为**合规的** H90=2。

### 阶段 B —— 冲 Tier 3（真·前沿，目标 1–2 周）
1. 同一个 cell 架构，从阶段 A 的权重 **warm-start**，扩到 Tier 3（p 9–16 bit / operand 64-bit）。
2. 沿用已验证有效的 anneal 阶梯（1e-3 → 3e-4 → 1e-4）+ grad clip（memory 记过：loss spike 会把 0.80 basin 踢出）。
3. 直接对标 Marcos 的 0.69：先复现"能到 ≥0.5 区间"证明串行 cell 在全范围不撞墙，再往 0.90 推。
4. **验收门 B**：held-out（secret-seed 风格）t3 ≥0.90 → **H90=3，超越现有所有基线一个 tier**。

### 阶段 C —— 收 Fermat / drift 残差（与 B 并行）
1. 诊断我自己的 cell 是否同样在稀疏最坏点掉分（复刻 Robby 的密度扫描）。
2. 若是，上 **on-policy DAgger**（专门在最稀疏最大幅度点 rollout 采样纠错）；辅以 EWC/L2-SP 防止修 Fermat 时弄坏别的族。
3. **验收门 C**：Fermat 族 exact-match 与其他族齐平，且无"把失败搬到别处"。

### 阶段 D —— 更高 tier / Level 1（截止前视余量）
- Tier 4+：串行 cell 天然衔接原 RNS 计划里的 U2（标量长模乘）——U2 之前 RED 的根因正是"无串行路径"，现在有了。可重启 U2 kill-test。
- Level 1（学到的 controller / lazy reduction）**仅在 Hongyue 的裁决确认允许后**再投入。
