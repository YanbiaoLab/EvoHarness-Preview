# P0.1 选择抗噪:完整方案(跨域)

2026-07-26。**方案不等待剩余测量** —— 已测到的事实足以定架构,未测的只
影响一个参数(见 §5)。

## 0. 两个域的实测事实

| | IMO | modmul(QUICK,3 次重复) |
|---|---|---|
| 候选 | 确定性 agent(三模型温度全 0) | **训练一个模型** |
| 重复评估 | 温度 0,残余抖动为二阶项 | **确有随机**:tier2 精度 0.2↔0.4 |
| fitness 噪声 | 题目抽样主导,理论 sd ≈ 0.14 | sd ≈ 0.0010 |
| 典型效应量 | ~0.05 | ~0.0018 |
| **信噪比** | **≈0.4** | **≈1.8** |
| 病因 | **噪声太大** | **度量把信号压扁 100 倍** |

关键量化:modmul 的 `fitness=(h90+overall)/11` 把"某层精度翻倍"压成
+0.0018;而跨过某层 0.9 会突跳 +0.091(50 倍)。地形是**几乎全平 +
偶尔悬崖**,对进化搜索最不友好的形状之一。

**共同解法**:别拿标量 fitness 做比较,拿**域自报的向量**做配对比较。
IMO 是逐题得分,modmul 是逐层精度。两个域的病不同,这一刀都对症。

## 1. 配对向量比较(先做,零成本,两域通用)

父子**本来就在同一批单元上评估**,是配对设计,却一直被当非配对读。
配对差里单元难度项直接抵消,残余方差只来自变化的那几个单元。

- **抽象**:域报告一个可比向量。`BehaviorSignature.pass_vector` 现在是
  `tuple[bool, ...]`,**必须放宽成 `tuple[float, ...]`** 才能装 modmul
  的逐层精度。
- **判据**:布尔向量用 McNemar / 符号检验;连续向量用 Wilcoxon 符号秩。
  输出一个 p 值和方向,不再是裸 Δ。
- **三处消费**:
  1. 反思器的 noise 判据 —— **替换掉 `|Δ| ≤ 1/n_items`**。那是我在 IMO
     语境下拍的,在 modmul 上 `n_items` 是被截断的反馈条数、与计分无关,
     会给出乱七八糟的判定;
  2. `RegressionSoftPenalty` 的"回落"判定 —— 现在用标量比较,应改为
     "配对检验显著变差"才计入连败;
  3. 经验条目记录 flips(变好/变坏的单元数),供 prompt 渲染。
- 落点:`evoplus/feedback.py`(签名放宽 + `paired_verdict`)、
  `evoplus/reflection.py`、`evoplus/behavior.py`、`evoplus/experience.py`。

## 2. 确认协议:harness 决策,域供能力

"第二意见"在两域含义相反,必须关进域内:

```python
@runtime_checkable
class Confirmable(Protocol):
    """A second, independent opinion on a candidate."""
    def confirm(self, cand, workdir, attempt: int) -> EvalReport: ...
```

- **IMO**:在**确认题集**上评(更多题目)。必须与终选集不重叠,否则
  确认即过拟合;
- **modmul**:**换随机种子重训**(重复评估在这里真有东西可平均);
- 未实现的域:不确认,退回当前行为(向后兼容)。

**harness 侧固定**:只在候选**声称刷新最优**时触发确认(幸运者诅咒只在
取最大值时咬人),合并后仍是最优才占据 best 位置;否则保留 fitness 但
不占位。实测频率约每 run 5 次 → **额外约 33% 评估预算,而非 K 倍**。

落点:`evocore/interfaces.py` 加协议;`SearchLoop` 在 best 更新处调用;
`recipes/common.py` 透传;IMO/modmul 各自实现。

## 3. 承诺用悲观,探索用乐观

`EvalReport` 加 `n_units` / `sem`;`Candidate.fitness_lcb = fitness - z*sem`。

- **父代选择用点估计** —— 探索要乐观,压低高方差候选会扼杀探索;
- **best 追踪 / 终选用 LCB** —— 承诺要悲观。

这化解文档里标出的矛盾:imp@k 的 `max` 最乐观、P0.1 的 LCB 最悲观,
**区分"探索"与"承诺"两个场景即可共存**,不必二选一。

⚠️ **modmul 例外**:`h90` 是阶跃项,对称区间会误描述它。置信度应算在
**连续量(逐层精度)**上,再传播过阈值(即"第 t 层 ≥0.9 的概率"),
而不是直接给 fitness 套 ±区间。

## 4. 度量本身(modmul 专属,可能比抗噪更重要)

压缩 100 倍不是噪声问题,是**度量设计问题**。两个方向:

- **选择用 `overall_accuracy`(连续、有梯度),`h90` 只进终评报告**
  —— 让搜索有坡可爬,排行榜键仍按官方口径报告;
- 或**软化 h90**:`Σ_t sigmoid((acc_t - 0.9)/τ)`,保留"跨阈值有奖励"的
  语义但给出梯度。

这条不动 harness,只动 `experiments/modmul/grade.py` 的 fitness 定义,
属于域内决策。

而崩溃,已加重试 + 分段落盘。它决定的是:IMO 的 `confirm()` 要不要**在
